# Contributing

Thank you for helping. Three kinds of contribution matter most right now, in this order.

1. **Cases where it reads wrongly.** Real correspondence (anonymised) where a message was read as supporting,
   refuting or settling nothing when it did not, with the requirement it was read against. Open an issue with the
   "Misreading" template. These become evaluation data, and they are what the next training run needs most.
2. **Reports from use.** If you tried it on real work: what you tracked, what it got right, what it got wrong, and
   whether it saved you any time. No person has been measured using it yet, so every report counts.
3. **Code.** Bug fixes, importers for more sources (read-only), templates for more workflows, other languages.

## How a misreading becomes evaluation data

A maintainer runs `python scripts/misreadings.py sync`, which rebuilds `evals/misreadings.jsonl` from the issues
labelled `misreading`. Only reports whose author answered "Yes" to the form's consent question are written there,
under CC BY 4.0 with the author and the issue as attribution; a report without consent is counted and nothing from
it is stored. Label an issue `invalid` or `duplicate` to keep it out. `python scripts/misreadings.py score` then
measures both released readers on the file, so every new training run can be checked against what people found.
Details are in [evals/README.md](evals/README.md).

## Working on the code

```bash
git clone https://github.com/jithinsaireddy/ease-delta && cd ease-delta
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest                          # needs no model and no network
ruff check src scripts tests
```

Tests use an oracle reader, so they run in about a minute on a laptop. A change to the exact core (ledger, graph,
logic, planner) should come with a property test, as the existing ones are.

## Rules of the project

- **Measure before claiming.** A new claim about accuracy or cost goes into a pre-registration (`docs/`) before the
  experiment, with its decision rule. `docs/RESULTS.md` is generated by `scripts/make_report.py`; never edit its
  numbers by hand.
- **Report what failed.** A hypothesis that was not supported is reported as not supported.
- **Nothing acts.** No code path may send, pay, submit or execute anything on anyone's behalf.
- **Readers read text.** Anything that turns a source into records must keep attribution in the text and use
  stable record ids and revisions.
- **Licences.** Training data must allow its use for weights released under CC BY-SA 4.0; non-commercial data may be
  used for evaluation only.

Commits: one change per commit, a message that says what and why. By contributing you agree that your contribution
is licensed under Apache-2.0 (code) and, for data, under the licence you state for it.
